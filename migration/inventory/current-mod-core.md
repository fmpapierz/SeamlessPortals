Slice: `common/src/main/java/com/warwa/seamlessportals/{api,chunk,client,compat,config,entity,network,portal}` + all NON-render mixins in `common/.../mixin/` (root package + non-render `mixin/client/`) + `fabric/src`, `neoforge/src`, and the build/loader setup.
Ground truth for dispositions: IP source at `C:/Users/warwa/ModDev/ImmersivePortalsMod/src/main/java/qouteall` (MC 1.21.3, Mojang mappings). Line numbers cited are from THIS repo unless prefixed `IP`.

Dispositions used:
- **REPLACE** — an IP subsystem does this job; the class is deleted and its job is re-implemented by porting the IP code.
- **DELETE** — the mechanism exists only because portals are blocks (or is legacy/dormant); it dies with the migration and nothing replaces it.
- **KEEP** — loader plumbing, faithful vanilla adaptation, or an already-IP-faithful port that carries over.
- **CARRY** — a fix for a real vanilla/26.2 behavior that IP-1.21.3 never had to face; must be re-verified against the ported crossing code, not blindly deleted.

## 1. Overview

This slice is the entire non-render half of the current block-portal mod: portal identity/registry/linking (`portal/`), teleportation for players/entities/projectiles (`entity/`, `client/SeamlessClientTeleport`), the custom server→client destination-dimension streaming stack (`chunk/`, `network/`), the client-side secondary-world manager (`client/PortalWorldManager` + friends), and the mixins that hook vanilla block/packet/entity lifecycles to make all of that fire. Architecturally it is a hand-rolled approximation of four IP subsystems: `qouteall.imm_ptl.core.portal.*` (portal identity — IP: a `Portal` **entity** with a full rigid transform; here: a `PortalInfo` value object derived by scanning `nether_portal` blocks), `teleportation.{Server,Client}TeleportationManager` (here: `SeamlessServerTeleport`/`SeamlessClientTeleport` bolted onto vanilla `ServerPlayer.teleportTo` + a client renderer promote/demote swap), `chunk_loading.*` (here: `PortalChunkTracker`'s ACK-ledger redirected-chunk streaming vs IP's `ImmPtlChunkTracking`/`ImmPtlChunkTickets` per-player chunk-loading graph), and `network.PacketRedirection[Client]` (here: bespoke `ModPayloads` wrapping a handful of vanilla packets vs IP's generic dimension-tagged redirect of ALL vanilla packets).

The migration replaces almost everything here. What survives is (a) the loader abstraction (`network/PlatformHelper` + the fabric/neoforge modules + buildSrc) — IP is Fabric-only and its `platform_specific` layer must be mapped onto this mod's ServiceLoader/multiloader scheme; (b) `client/SeamlessClientChunkMap`, which is already a line-faithful 26.2 port of IP's `ImmPtlClientChunkMap`; (c) config plumbing (its `portalRenderDistance` knob is explicitly IP's `indirectLoadingRadiusCap`); and (d) a small set of 26.2-specific vanilla adaptations (e.g. the `fireSpreadRadiusAroundPlayer` gamerule bypass) that IP-1.21.3 has no analog for because the vanilla mechanic didn't exist at 1.21.3.

## 2. Class-by-class inventory

### 2.1 `portal/` — portal identity, registry, linking (the heart of what gets replaced)

#### `PortalInfo` (149 LOC, common, immutable value object)
- **Responsibility:** describes one block-portal: type, dim, origin (min-corner portal block), axis (width direction), width, height; derived AABB, center, normal. Identity is a **deterministic UUID** hashed from `dim@x,y,z/axis` (PortalInfo.java:32-36) so client and server agree on ids without sync (width/height excluded so resizes keep the id).
- **Key API:** `containsPoint(Vec3)` (box inflate 0.1, :81), `intersectsMovement(Vec3 from, Vec3 to)` — the plane-straddle + t∈[0,1] + width/height bounds segment test used by ALL crossing detection (:96-115); `getIntersectionPoint` (:128); getters.
- **Geometry convention (load-bearing, verified):** `axis` = the direction portal blocks stretch (width). axis=X → face in XY plane, depth along Z; axis=Z → face in YZ plane, depth along X (:48-79).
- **MC classes:** `BlockPos`, `Direction.Axis`, `ResourceKey<Level>`, `AABB`, `Vec3`.
- **Disposition: REPLACE** → IP `portal/Portal.java` entity (origin/destination pos, `axisW/axisH` orthonormal basis, rotation quaternion, scale, `width/height`, shape) + `portal/PortalState.java`. The deterministic-UUID trick dies: IP portals are entities with real entity UUIDs, spawned/synced to clients by IP's dedicated `ImmPtlNetworking.PortalSyncPacket` (IP ImmPtlNetworking.java:134-143 — a `ClientboundAddEntityPacket` analog carrying id/uuid/entityType/dimensionId/pos/extraData, sent redirected).

#### `PortalTransform` (249 LOC, common, static math)
- **Responsibility:** the canonical source/dest coordinate mapping. Axis-local decomposition into (depth, width, height) via `toLocalCoords`/`fromLocalCoords` (:218-230). `transformPoint` = same-sign depth (the render/window parallax, 1:1 on same-axis links); `transformTeleportPoint` = depth-negated (:46-64); `transformVector` = depth-negated velocity for the mirrored entity pair (:167-180); `transformVelocityMotion` = plain same-sign local mapping — explicitly documented as "IP's `transformLocalVec` analog" (:199-202); `transformYaw` = ±90° on axis mismatch (:204-209).
- **Overshoot landing:** `MIN/MAX_EXIT_OVERSHOOT` 0.08/0.5 (:90-91), `sourceDepthOvershoot` (:94), `applyExitOvershoot` places the landing exactly the detected overshoot past the dest plane on the motion side (:156-165).
- **Crossing sign:** `crossingDepthSign(from,to)` — segment-delta depth sign, fallback to position side (:116-123); `crossingDepthSignFromState(pos,vel)` for the server-first fallback (:132-139).
- **Height mapping is floor-relative** (`origin.getY()`), not center-relative — different-height portals keep ground level consistent (:24-38).
- **Dead code:** `applyCoordinateScale` (:232-245) is private and never called — the 8x nether scale is applied only at LINK CREATION time (`PortalManager.computeExpectedDestination`), never per-transform. Per-crossing transforms are pure translation+axis-swap.
- **Disposition: REPLACE** → IP `Portal.transformPoint/transformLocalVec/inverseTransformPoint` (quaternion + scale based). The overshoot/sign machinery maps to IP `teleportation/TeleportationUtil.java` (its `Teleportation` record captures the crossing segment and computes the exit posture). NOTE: the yaw-only `transformYaw` model cannot represent IP's arbitrary rotations — do not port it; use IP's rotation application verbatim.

#### `PortalLink` (69 LOC, common)
- **Responsibility:** a directed source→dest pair of `PortalInfo` + convenience wrappers over `PortalTransform` (`transformTeleportPosition(Vec3,double exitSign)` composes teleport-point + overshoot, :34-38).
- **Disposition: DELETE** — IP has no link object; a `Portal` entity IS the directed link (its fields carry destination + transform), and the reverse portal is a second entity (`PortalExtension`/`PortalManipulation.createReversePortal`).

## 3. Mechanisms (precise flows)

### 3.1 Portal formation & linking (server)
1. Ignition: vanilla `PortalShape.createPortalBlocks` TAIL (`PortalShapeFormMixin`) → `PortalDetector.queueFormation(level, bottomLeft)` — deferred because it fires inside the fire block's `onPlace` (PortalDetector.java:14-25).
2. Next tick: `PortalChunkTracker.tick` → `drainPendingFormations` → `onNetherPortalFormed`: verify block, retire speculative prewarm entry, dedup vs tracker, walk origin (down + negative-width), measure WxH, → `PortalManager.onPortalFormed`.
3. `findOrCreateDestinationPortal`: expected pos = floor(origin×scale) (Y kept); try tracked dest portal ≤128 blocks not claimed by another link; else `PortalForcer.findClosestPortalPosition(expected, isNether, worldBorder)`; else `PortalForcer.createPortal(expected, axis)` + resize-to-source (obsidian ring first, portal blocks flag 18 second — self-destruct avoidance, PortalManager.java:421-457); else virtual link. All branches: `createLink` stores forward AND reverse keyed by `dim:x,y,z`, broadcast `PortalLinkPayload` to every player, pre-warm dest chunks (ticket radius 8).
4. Redundant discovery paths keep it converging: server periodic block scan every 40t within 4 chunks of players (PortalChunkTracker.java:337-389), `NetherPortalBlockMixin.entityInside`, `PortalForcerMixin` observing vanilla creations. All idempotent through the pos-key dedup.
5. Destruction: `NetherPortalBlockMixin.updateShape→AIR` and `ServerLevelBlockUpdateMixin` (portal→air) unregister BOTH sides + broadcast `PortalUnregisterPayload`.
- **Client:** portals discovered by chunk-scan (`ClientLevelMixin.onChunkLoaded`, palette-gated) register SHAPE only; links come exclusively from `PortalLinkPayload` (`PortalDetector.handlePortalLinkFromServer`).

### 3.2 Crossing detection + teleport (player, client-first)
1. Per-frame: `SeamlessClientTeleport.checkCameraCrossingPerFrame` (called from the render slice's `StencilPortalRenderer.prepareDestinationRender` at `renderLevel` HEAD) builds the camera segment last-frame → this-frame (player pos lerped by partial tick + eye height), tests `findPortalCrossing` (plane straddle + aperture bounds), and swaps BEFORE the frame renders. 20Hz fallback: `LocalPlayerMixin.tick` HEAD with the tick segment.
2. `performCrossing`: exitSign = segment depth sign; dest pos = depth-negated transform + overshoot(|source depth|, clamped 0.08..0.5) on the motion side; vel = same-sign local map; yaw ±90 on axis mismatch.
3. `doVisualSwap` (see §2.5) — the client is now fully in the dest dim visually; `ClientPortalCrossingPayload(portalId, swapSeq, exitSign)` goes to the server.
4. Server `handleClientInitiatedCrossing`: link lookup by UUID, dim match, box-inflate-8 proximity, sign sanitize → `performCrossing`: `PortalChunkTracker.onPlayerCrossing` (suppress + seed), vanilla `teleportTo` with `Relative.union(DELTA, ROTATION)`, explicit server-side rotation set, shared-flags redirty, `ClientboundSeamlessMovePayload` echo.
5. Client reconcile: stale if `swapSeq < swapSeqCounter`; else ACK-only (<4 blocks) or desync snap; fallback branch performs the deferred swap when the client never detected.
6. The vanilla respawn packet still arrives; `HandleRespawnMixin` neuters it (idempotent branch) or, for superseded double-crossings, points `this.level` at the cached dest level while visuals stay (stale branch).
- **No server-side player fallback exists** (LocalPlayerMixin.java:28-39) — a missed client detection silently strands the player. Migration task #11.

### 3.3 Crossing (non-player)
`EntityMixin.tick` HEAD (server, non-players): advance `lastTickPos` segment EVERY tick; skip if cooldown or attached boost firework; on plane-crossing → `PortalTeleporter.teleportEntity`: motion-signed landing + `TeleportTransition(DO_NOTHING)` vanilla recreate + hurt-state carry + cooldown 2. Projectiles use the parallel `ProjectilePortalHandler` (pos→pos+vel segment, intersection-point based, ender-pearl special case) — two paths to be unified by the migration.

### 3.4 Destination chunk streaming (the ACK ledger)
Server per tick per player: graduated+capped radius per nearby link (≤4 nearest); residency ticket re-added; ring-ordered needed set; sends ≤12/tick (32 cold) redirected REAL `ClientboundLevelChunkWithLightPacket`s for loaded (`getChunkNow`) chunks not acked/inflight, ≤64 inflight, 10s inflight TTL. Client: netty enqueue → 3ms/tick budgeted apply under a full level/renderer/listener context switch → verify `hasChunk` → batch-ACK per dim. Server moves inflight→acked only on ACK. Crossing: acked-set (filtered to the dest tracking-view shape) arms one-shot suppression of `ChunkMap.markChunkPendingToSend`; old dim seeded with vanilla's exact held-set predicate. Rules distilled in memory: any "client holds X" claim must be ACK/predicate-verified and survive client retention.

### 3.5 Live mirror (blocks/entities/fire)
- Blocks: `LevelChunk.setBlockState` RETURN (server main thread, real change) → per-player link-proximity filter → `BlockUpdateMirrorBuffer` (dedup by pos) → one `RemoteBlockUpdateBatchPayload` per player/dim at tick end → `RemoteBlockUpdater.applyBatch`: `setBlock(flag 0)` + one dirty+compile per affected section.
- Entities: `PortalEntityTracker` diff/dedup → Add(+data+equipment)/Move/Remove payloads → `RemoteEntityApplier`: adopt-in-place when same id+uuid+type (no blink/construction stall); mirrors are `noPhysics=true`, zero velocity, position-driven via `InterpolationHandler.interpolateTo`.
- Fire: `ServerLevelFireSpreadMixin` lets `canSpreadFireAround` pass for cross-dim watchers (26.2 gamerule).
- Liveness: client `tickRemoteWorlds` fully ticks each scope-live secondary (entities, block ticks via `tick(()->true)`, `pollLightUpdates`), `lateUpdateSecondaryLight` runs `runLightUpdates` at frame end (IP `lateUpdateLight`), `tickCachedParticles` animate-ticks the dest around the DEST PORTAL ORIGIN every other tick (IP parity, PortalWorldManager.java:1600-1608) into a per-dim `ParticleEngine`.

### 3.6 Client secondary-world lifecycle
Create (per dim, lazy) → stream/feed → scope-live maintenance (tick/pump/evict, keyed to nearby-portal presence with a 5s grace) → promote on crossing (meshes preserved; extractor identity re-pointed; SOG warm-repaint; entity adoption) → demote of the outgoing dim (new per-dim extractor; level's extractor field re-pointed; adoption armed) → cleanup on disconnect/kick (`ClientLevelMixin.disconnect` + `MinecraftMixin.updateLevelInEngines(null)`).

## 5. Registration & wiring

**There is NO registry content today.** The mod registers zero blocks, items, or entity types — portals are recognized purely by scanning vanilla `nether_portal` blocks. ⇒ The migration must ADD a registration path for IP's `EntityType<Portal>` family (+ `PortalPlaceholderBlock`, + IP's `LoadingIndicatorEntity`), and none exists to copy. Loader shapes to use: Fabric — `Registry.register(BuiltInRegistries.ENTITY_TYPE, ...)` from `SeamlessPortalsModFabric.onInitialize`; NeoForge — `DeferredRegister`/`RegisterEvent` on the mod bus in `SeamlessPortalsModNeoForge`. This wants a new `PlatformHelper`-style seam (or an expansion of it) since IP's Fabric-only `IPModEntry` registration cannot be used as-is. Verified: IP's registration core is ALREADY loader-agnostic — `IPModMain.registerEntityTypes(BiConsumer<ResourceLocation, EntityType<?>>)` (IPModMain.java:162) and `IPModMain.registerBlocks(BiConsumer<ResourceLocation, PortalPlaceholderBlock>)` (IPModMain.java:155) hand `(id, object)` pairs to a loader-supplied consumer (the Fabric `IPModEntry` in `platform_specific/` supplies `Registry.register`); the port keeps that BiConsumer shape and supplies a Fabric consumer + a NeoForge `RegisterEvent`/`DeferredRegister` consumer. The `EntityType` build parameters (tracking range, update interval, velocity updates, non-summonable) live on the static `ENTITY_TYPE` fields of each portal class (`Portal.ENTITY_TYPE`, IP Portal.java:87, built by `createPortalEntityType` :94-108; the other portal classes follow the same pattern) and must be preserved verbatim through both loaders.

**Instantiation/tick wiring today:**
- Server singletons: `PortalManager.getServerInstance()` lazily; `PortalChunkTracker`/`PortalEntityTracker` constructed as FIELDS of the loader entrypoint classes (Fabric both; NeoForge chunk-tracker only) — `PortalChunkTracker`'s constructor publishes itself to the static `ACTIVE` (PortalChunkTracker.java:69-71).
- Ticket types register in STATIC INIT of `PortalChunkTracker`/`PortalEntityTracker` via `TicketTypeInvoker` — deliberately early, because the TICKET_TYPE registry freezes before first-formation time (PortalEntityTracker.java:212-218).
- Server tick: Fabric `ServerTickEvents.END_SERVER_TICK` → chunkTracker.tick → entityTracker.tick → tickPortalPreWarm → BlockUpdateMirrorBuffer.flush. NeoForge `ServerTickEvent.Post` → chunkTracker.tick + flush only.
- Client tick: Fabric `ClientTickEvents.END_CLIENT_TICK` → RedirectedPacketApplier.drainPending → advanceCompilePipelines → syncTimeToCachedLevels → tickRemoteWorlds → tickCachedParticles → evictUnboundedStores (order is load-bearing: chunks land before the pump; ticks before render). No NeoForge client tick exists.
- Render hook (owned by render slice, listed for wiring completeness): Fabric `LevelRenderEvents.AFTER_TRANSLUCENT_TERRAIN` → `StencilPortalRenderer.renderPortals()`.
- Payloads: common defines them (`ModPayloads`); each loader registers types + receivers (`FabricPlatformHelper.registerPayloads/register{Server,Client}Handlers`; NeoForge partial). Send path: `PlatformHelper.getInstance()` via ServiceLoader.
- Client lifecycle teardown: `ClientLevelMixin.disconnect` + `MinecraftMixin.updateLevelInEngines(null)` + `MinecraftMixin.close` → clearPending/clearAll/resetClient/PortalWorldManager.cleanup/SeamlessClientTeleport.onDisconnect. Server teardown: `SERVER_STOPPING` → resetServer + tracker clears. `onPlayerDisconnect` hooks exist on both trackers (sentChunks/inflight/suppress + tracked/moveSnap) and `BlockUpdateMirrorBuffer.clearPlayer` — but **grep-verified: ZERO call sites anywhere in the repo** (PortalChunkTracker.java:748, PortalEntityTracker.java:481, BlockUpdateMirrorBuffer.java:81 are all uncalled). Per-player server state currently leaks across relogs until the dim-retention pruning catches it; the IP port's wiring must add a real player-disconnect hook on both loaders.
- Config: loaded once at Fabric `onInitialize` (`FabricLoader.getConfigDir()`); NeoForge never loads it (defaults only) — another parity gap.
- Mixins: single config `seamlessportals-common.mixins.json` shipped from `:common` resources into both loader jars (buildSrc source-merge), plugin-gated for Sodium. AW (Fabric/loom) + AT (NeoForge/MDG) carry the same four wideners and must be edited in pairs.

**Known parity gaps to respect in the port:** NeoForge has no client init, no entity tracker tick, no prewarm tick, no config load, and registers 5/18 payloads — the Fabric module is the reference implementation; the migration should target the `PlatformHelper` seam so NeoForge inherits the new wiring rather than hand-porting twice.
