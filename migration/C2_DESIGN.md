### 0.3 Resolved conflicts (each re-read against the ground truth)

1. **Swap payload: 2-field remap (A/C, probe-may-grow) vs widened persistent context (B).** RESOLVED FOR B's ARCHITECTURE. The 091 map is decisive on both counts: `renderLists` is regenerated every `setupTerrain` from persistent tree state (`RenderListProvider.createRenderLists(Viewport)` off `renderTree`; map #2: "renderLists is regenerated per-frame from the SectionTree… Render-list isolation across portal layers must be re-derived against this tree model, not a 2-field swap"), and the cull is frame-decoupled async (map #4 ASYNC EXECUTION). A fresh-empty 2-field context therefore either shows nothing forever (its scheduled CullTask dies with it) or leaks tree/cull mutations into the dim's persistent state on same-dim portals. §3.1 is the widened-persistent design; the exact field census and the convergence behavior are C2-0 probes (P3/P10) that can only SIMPLIFY the design (e.g. if `updateChunksImmediately`/FlawlessFrames turns out to force a synchronous cull path usable per-pass), never silently keep the naive remap.
2. **#3 MixinSodiumRenderRegion: ship (B) vs probe-gated (A/C).** RESOLVED: DEFAULT-SHIP IN C2-1, probe-downgradable. The map confirms the hazard structurally persists (`ChunkRenderList.reset(int)` fired by `VisibleChunkCollector` when `getLastVisibleFrame() != frame`; the @Overwrite site + `ChunkRenderList(RenderRegion)` ctor EXISTS-IDENTICAL) but explicitly instructs: "Verify the recursive-portal frame increment still triggers a mid-frame region-list reset… before assuming the per-layer-list fix is still required." P5 runs in C2-0 WITH the D1 interplay in mind (if the RSM frame counter joins the swap set, the portal pass may never advance the main frame counter — D1 itself may neutralize the #3 trigger). Ship on structural default; downgrade to DEFER-DORMANT only on positive probe evidence, ledgered.
3. **Culling chain: in-C2 (A, B) vs deferred (C).** RESOLVED: IN-C2 as stage C2-3, using B's viewport-carried snapshot design — C's deferral rationale ("needs its own design pass") is answered by B having produced that design, grounded in the map's testSection/async findings. Floor = named perf-only deviation (culling off under sodium), A/B-levered in-stage.
4. **Stage order: culling before clipping (A, B) vs clipping early (C).** RESOLVED: CLIPPING BEFORE CULLING (C2-2 then C2-3). Clipping is a CORRECTNESS artifact (dest terrain pokes through the plane — the classic break) and its landing retires the interim GL_CLIP_DISTANCE0 crutch; culling is pure perf with an acceptable floor. Counterweight (clipping touches shared vanilla-clip code, A's argument for shipping it last) is answered by C's sibling-mixin isolation (§3.3.2): the sodium branch lives in a NEW sibling mixin keyed on the `sodium:` namespace — structurally inert for plain runs.
5. **Gate evolution: commit sodium activation at stage 1 with warn (A) vs default-false + lever until a user decision (B/C).** RESOLVED: B/C's shape with A's notice design. `ExperimentalCompatGate.ENABLE_SODIUM_IRIS_COMPAT` stays DEFAULT FALSE in committed code at every intermediate stage; live rounds flip it via a JVM-property lever; `detectAndGateRenderCompat` is restructured into PER-MOD verdicts at C2-1 (sodium path exists behind the gate, iris stays warn+force until C2-4); when the sodium path IS active it emits A's one-shot honest chat notice naming exactly what is still missing at that stage. The default-ON flip for sodium is a USER decision at the C2-2 boundary (once the clipping artifact story is clean); the interim unclipped state is warn-eligible, not force-eligible, per B's 3d analysis (our flag-ON renderer is stencil-direct, so a missing front-clip cannot leak full-screen — wrong content stays WITHIN the aperture, exactly IP's own supported `enableClippingMechanism=false` degradation).
6. **Iris scope: full shaders-ON ladder in C2 (A) vs none (B) vs detection+parity+honest-off (C).** RESOLVED: C's end-state IS C2's iris deliverable (stage C2-4); A's shaders-ON re-expression (IrisCompatibility SHAPE onto `renderDestWorld` — tracer C: lowest coupling, pure GL `glCopyImageSubData` + IP core shaders, zero Iris internals) is a USER-DECISION checkpoint at C2 close: an optional in-C2 extension stage with its own design workflow, or post-C2. B's omission of iris is rejected (the C2 mandate covers both mods; today's blanket iris force-off must at minimum become shaders-OFF parity + honest shaders-ON degradation).
7. **B4 pipeline access: keep IP-exact reflection (A/C) vs public API.** RESOLVED: keep the reflection (tracer 3 javap-PROVES `LevelRenderer.pipeline` name/type/target unchanged on 26.2+Iris 1.11.2 — IP-faithful and proven) BUT replace the `Helper.noError` silent swallow with a one-time LOUD resolve check at invoker install (named deviation D7); `Iris.getPipelineManager().getPipelineNullable()` ledgered as the S20-era hardening candidate (analogous to the unbound-holder/bindValue watch item).
8. **FlawlessFrames/freshness: own stage (A) vs folded (B/C).** RESOLVED: folded into C2-1 (one trivial EXISTS-IDENTICAL mixin + a facade-internal call swap — not worth a stage boundary).
9. **TransformPatcher (iris FILE 7): clipping stage (C, conditionally) vs shaders-ON stage.** RESOLVED: DEFERRED WITH THE SHADERS-ON RENDERER. Reasoning from our own C2-4 end-state: shaders-ON routes to `rendererDummy` → no dest passes run under shaders → `FrontClipping` never arms → iris-patched-terrain clipping is MOOT until a shaders-ON renderer exists. What C2-2 DOES need is the double-patch guard + a C2-4 live check that sodium clipping still works with iris INSTALLED but shaders OFF (iris routes sodium GLSL through `patchSodium` — whether that path engages with shaders off is probe P11).
10. **Baseline sodium boot sanity (A's P2, unaddressed by B/C).** ADOPTED with a pre-decided contingency: if the C2-0 baseline round shows the main world blank/unmeshed under sodium flag-ON (because `ImmPtlClientChunkMap` replaces the vanilla chunk cache and Sodium's own load hook never fires while A5/A6 are invoker-dead), then the chunk-tracker feed becomes an UNCONDITIONAL-when-sodium-present carve-out from the compat gate (named deviation D11, same family as the D3 unconditional-worldgen seam: pure correctness plumbing that must not depend on the experimental gate). If the baseline is fine (e.g. flag-ON main world still meshes via some path), A5/A6 ride the normal invoker activation.
