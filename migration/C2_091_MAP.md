### Design implications (swap)
- FILE #4 (OcclusionCuller) is redesign-not-remap. The cull is now asynchronous (CullTask implements Callable, submitTo(asyncCullExecutor), results polled via isDone() a later frame) AND multi-visitor (3 GraphOcclusion/VisibilityTesting visitors, CullType WIDE/REGULAR/LOCAL, cullResults map + renderTree). IP's box-portal iteration-origin retarget + tolerant-frustum reads render-thread portal globals (PortalRendering.isRendering/getRenderingPortal, CHelper camera) at findVisible HEAD â€” that runs on the wrong thread and wrong frame. Redesign must EITHER capture the portal context at CullTask SCHEDULE time (render thread) and pass it into the task so findVisible reads task-local state, OR leave box-portal special iteration (already lever-gated behind IPGlobal.boxPortalSpecialIteration, default off) disabled for the 0.9.1 port. The single re-site point for the origin swap is the getChunkCoord() call at findVisible offset 67 (init/initWithinWorld no longer call it â€” they read the origin field).
- FILE #5 (advanced frustum culling) redesign: the per-section frustum test moved from Frustum.testAab(FFFFFF) to Frustum.testSection(FFF) inside Viewport.isBoxVisible(III), and the arg shape changed from a 6-float camera-relative AABB to a 3-float section CENTER. IP's canDetermineInvisibleWithCameraCoord(float x6) predicate must be re-derived to take a section-center (reconstruct the section AABB from center +/- radius), OR re-anchor the redirect on the surviving 6-float path Viewport.isBoxVisibleDirect(FFFF)->testAab(FFFFFF) if that path is what section culling actually consults (verify which of testSection vs isBoxVisibleDirect gates the terrain BFS visibility in the new async visitor).
- FILE #2 (context swap) redesign: swapping only renderLists + renderDistance no longer isolates a same-world portal-dest render. RenderSectionManager now holds per-world SectionTree renderTree, a per-CullType cullResults Map<CullType,SectionTree>, renderableSectionTree (RemovableMultiForest), SectionStorage renderSections, and the async pendingTask/cullResults â€” and renderLists is regenerated per-frame from the SectionTree via RenderListProvider.createRenderLists. Render-list isolation across portal layers must be re-derived against this tree model, not a 2-field swap. Separately, retarget the isSectionVisible(III) entity-cull-disable @Inject to RenderSectionManager.isBoxVisible(DDDDDD)Z HEAD.
