## Cross-cutting notes

1. **Everything raw-GL in this slice is third-party compat** (Iris/Sodium renderers + helpers). The verdicts above record the 26.2 mechanisms for completeness, but per the inventory's own SKIP table these port only if/when Sodium/Iris exist for 26.2 — and then against *their* new internals, not by line-porting.
2. **The invoker-pattern base classes (`GravityChangerInterface`, `SodiumInterface`, `IrisInterface`, `IPPortingLibCompat`) are pure-Java no-ops** — nothing in their base implementations touches a changed MC API except `IPPortingLibCompat` (stencil duck, GONE §1) and `SodiumInterface.markSpriteActive`'s `TextureAtlasSprite` (SAME §3). They port as-is; only `On*Present` subclasses are version-blocked.
3. **The wand and dim-stack GUI are the two big rewrite surfaces** in this slice: wand overlay drawing → Gizmos/submitCustomGeometry; all screens/lists → GuiGraphicsExtractor extract model. Their *logic* (state machines, RPC, drag solvers, MVC controllers) is MC-API-clean and ports unchanged.
4. **Alternate dimensions carry the two hard worldgen gaps**: definalized `NoiseBasedChunkGenerator` (AW+AT) and the re-derivation of `noNewCaves` — the *only* missing piece of IP's skyland router formula `noNewCaves(slideEndLike(getFunction(BASE_3D_NOISE_END), 0, 128))` (`NormalSkylandGenerator.java:133-139`); the other invoker targets port with verbatim descriptors (SAME §3). The error-terrain/chaos generator path has no blockers (all its types SAME §3).
5. `MixinChunkStatusTasks_BedrockReplacement` — flagged version-fragile by the inventory — turned out to be the **least** fragile: the 26.2 signature is verbatim identical (`ChunkStatusTasks.java:169-171`).
