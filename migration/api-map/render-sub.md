# 26.2 API Map: Render Context / Optimization / Renderer Family

Maps every MC API touchpoint from `migration/inventory/render-sub.md` §4 to its fate in MC 26.2.

- 26.2 citations are relative to `C:/Users/warwa/ModDev/mc262-ref` (Mojang mappings, decompiled vanilla).
- IP citations are relative to `C:/Users/warwa/ModDev/ImmersivePortalsMod/src/main/java/qouteall/` (IP 1.21.3), as in the inventory.
- Pre-verified companion: `MIGRATION_API_MAP.md` (repo root) — the submit→prepare→execute headline, LevelRenderer/LevelExtractor split, RenderPipeline/GpuFormat details. This document does not repeat what that file already proves; it cross-references it as `[API-MAP §…]`.

**Two cross-cutting facts that shape almost every verdict below (read first):**

1. **The frame is split into extract → render.** `GameRenderer.extract(DeltaTracker, boolean)` (`net/minecraft/client/renderer/GameRenderer.java:379-394`) captures ALL world/camera/options state into `GameRenderState`/`LevelRenderState`/`CameraRenderState` on the game thread side of the frame; `GameRenderer.render(DeltaTracker, boolean)` (`GameRenderer.java:396-450`) then draws exclusively from that captured state. `Camera` per-frame setup moved to `GameRenderer.update(DeltaTracker)` → `Camera.update(DeltaTracker)` (`GameRenderer.java:372-377`, `net/minecraft/client/Camera.java:93-112`). Every "swap state then re-render" IP mechanism must decide whether it intervenes at extract time (state capture), at render time (drawing), or both — one hook is no longer enough.
2. **Reversed-Z depth.** Vanilla clears depth to **0.0** (`GameRenderer.java:404-408`, `:439`, `LevelRenderer.java:197-206` — `clearColorAndDepthTextures(..., 0.0)`) and the default depth test is `GREATER_THAN_OR_EQUAL` (`com/mojang/blaze3d/pipeline/DepthStencilState.java:8`, `DEFAULT`; see [API-MAP appendix]). Every depth constant and comparison in the stencil renderer's choreography (clear-view-area-to-farthest, `glDepthFunc`, `glDepthRange`) must be sign-inverted: **farthest is now 0.0, not 1.0**.

### G1. `Camera.setup(BlockGetter, Entity, boolean, boolean, float)` + `MixinCamera` RETURN inject (position override)
- **IP usage:** `WorldRenderInfo.adjustCameraPos(Camera)` wired at `Camera.setup` RETURN (`mixin/client/render/MixinCamera.java:41-51`) — how the inner layer's camera gets its transformed position; `FogRendererContext.getFogColorOf` builds a throwaway `new Camera()` and force-sets pos/focused entity (`FogRendererContext.java:86-88`).
- **26.2:** `setup` does not exist (full read of `net/minecraft/client/Camera.java:1-535` — no such method). Per-frame camera positioning is `Camera.update(DeltaTracker)` (`Camera.java:93-112`) → `alignWithEntity(float)` (`Camera.java:249-295`), which calls protected `setPosition(Vec3)` (`Camera.java:353-356`) / `setRotation(float,float)` (`Camera.java:339-347`).
- **Replacement mechanism:** the camera *position consumed by rendering* is `CameraRenderState.pos`, written in `Camera.extractRenderState(CameraRenderState, float)` at `Camera.java:127` (`cameraState.pos = this.position()`). The faithful override point for "force the camera position for the active WorldRenderInfo" is either (a) inject at `Camera.update` RETURN and call the (protected → invoker/AT) `setPosition`, or (b) override `cameraState.pos` after `extractRenderState`. Note `setLevel(@Nullable ClientLevel)` is now public (`Camera.java:491-493`) and `setEntity(Entity)` is public (`Camera.java:411-413`) — the throwaway-camera pattern needs fewer ducks than in 1.21.3, but `initialized` is private and only set in `update()` (`Camera.java:110`), and `getFluidInCamera()` returns `FogType.NONE` when `!initialized` (`Camera.java:437-440`) — a mod-built Camera must set `initialized` (accessor) or fluid-in-camera silently reads NONE.

### G2. `FogRenderer.setupColor(Camera, float, ClientLevel, int, float)` + the six private statics (`fogRed/fogGreen/fogBlue/targetBiomeFog/previousBiomeFog/biomeChangedTime`)
- **IP usage:** `FogRendererContext.getFogColorOf` invokes `setupColor` and reads the statics via `MixinFogRenderer` shadows (`FogRendererContext.java:91-97`, `mixin/client/multiworld_awareness/MixinFogRenderer.java:11-22`).
- **26.2:** `FogRenderer` is fully rewritten as an **instance** class at `net/minecraft/client/renderer/fog/FogRenderer.java` (was static-heavy in `net/minecraft/client/renderer/`). The only static left is a global `fogEnabled` toggle (`FogRenderer.java:47`, `toggleFog()` `:163-165`). There are **no color/biome-interpolation statics** — full read `FogRenderer.java:1-236`.
- **Replacement mechanism:** `public FogData setupFog(Camera camera, int renderDistanceInChunks, DeltaTracker deltaTracker, float darkenWorldAmount, ClientLevel level)` (`FogRenderer.java:167-186`) computes color into `FogData.color` (`net/minecraft/client/renderer/fog/FogData.java:15`) via private `computeFogColor(...)` (`FogRenderer.java:87-161`). Vanilla call site: `GameRenderer.extractCamera` (`GameRenderer.java:632-639`), result stored on `cameraState.fogData`. **`getFogColorOf(destWorld, pos)` re-derivation:** call `fogRenderer.setupFog(...)` with a Camera whose `level`/`position`/`entity` are configured for the destination (see G1 caveats) — no `Minecraft.level` reassignment is required by `setupFog` itself (it takes the level as a parameter), though `FogEnvironment` implementations read only `camera`/`level` args (e.g. `WaterFogEnvironment.java:18-28`). The `FogRenderer` instance is `GameRenderer`'s **private** field with no getter (`GameRenderer.java:119`) — accessor mixin required, or the mod constructs its own instance (ctor allocates GPU ring buffer, `FogRenderer.java:51-64`).
- **Fog *delivery* changed too:** fog is consumed as a `GpuBufferSlice` UBO — `fogRenderer.updateBuffer(FogData)` writes the single per-frame `WORLD` ring-buffer slot (`FogRenderer.java:188-202`), `getBuffer(FogMode)` slices it (`:76-85`), and the slice is passed INTO `LevelRenderer.render(..., GpuBufferSlice terrainFog, Vector4f fogColor, ...)` (`net/minecraft/client/renderer/LevelRenderer.java:156-165`) and re-armed per pass via `RenderSystem.setShaderFog` (`LevelRenderer.java:393`, `:476`, `:495`). **`WorldRenderInfo.hasFog=false` / `MyRenderHelper` fog-off maps to `getBuffer(FogMode.NONE)`** — the pre-built "empty fog" buffer with all distances `Float.MAX_VALUE` (`FogRenderer.java:55-63`, `:82`), which is vanilla's own fog-disabled representation (also used by the global `fogEnabled` toggle, `:77-79`). **Design note (honest):** the ring buffer holds ONE `WORLD` slot per frame (`endFrame()` rotates, `FogRenderer.java:72-74`); the GPU reads the slot at pass execution, so writing dest-world fog into the same slot mid-frame corrupts whichever passes execute later. Rendering a second world with different fog per frame needs its own buffer (own `FogRenderer` instance or own `MappableRingBuffer`) — UNKNOWN-NEEDS-DESIGN on exact ownership, mechanism itself is clear.

1. **Reversed-Z depth vs the stencil choreography** (G8/S5/C8): every depth clear/func/range constant in `RendererUsingStencil` steps 4/7 (`clearDepthOfThePortalViewArea`/`restoreDepthOfPortalViewArea`) inverts.
