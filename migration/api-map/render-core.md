## Cross-cutting 26.2 facts (read first)

1. **Submit → prepare → execute** (API-MAP headline): no `MultiBufferSource`, no immediate `RenderType.draw`. Render code pushes into `SubmitNodeCollector`/`SubmitNodeStorage`, `FeatureRenderDispatcher.prepareFrame(...)` builds a `PreparedFrame`, draws issue against `com.mojang.blaze3d.systems.RenderPass`.
2. **Extract/render split**: per frame, `GameRenderer.extract(...)` (`net/minecraft/client/renderer/GameRenderer.java:379-394`) fills `GameRenderState`/`LevelRenderState` via `Minecraft.levelExtractor.extract(deltaTracker, mainCamera, worldPartialTicks)` (`GameRenderer.java:389`); then `GameRenderer.render(...)` (`:396`) → `renderLevel(DeltaTracker)` (`:525`) draws **from the extracted state only** (`gameRenderState.levelRenderState`, `:531-535`). Any portal-pass re-render must produce its own extracted state first (see GONE §G1).
3. **Reversed-Z depth**: default depth compare is `GREATER_THAN_OR_EQUAL` (`com/mojang/blaze3d/pipeline/DepthStencilState.java:9`), default depth clear value is `0.0` (`com/mojang/blaze3d/systems/RenderSystem.java:36`; `GameRenderer.java:439` `clearDepthTexture(..., 0.0)`). Every IP depth trick (view-area depth punch, "write far depth", depth-based layering) must flip its convention.
4. **A Vulkan backend exists** (`com/mojang/blaze3d/vulkan/VulkanBackend.java:1` and the whole `com/mojang/blaze3d/vulkan/` package, alongside `com/mojang/blaze3d/opengl/GlBackend.java`). All raw-GL mechanisms (clip planes, stencil, occlusion queries, `glCullFace`) are valid **only under the GL backend**; there is no vanilla cross-backend abstraction for any of them (queries: only timestamp pools, `com/mojang/blaze3d/systems/GpuDevice.java:184` `createTimestampQueryPool`).
5. **Final-field swap pattern**: the mutable `Minecraft`/`GameRenderer` state IP swaps per portal pass is now largely `public final`/`private final` (`Minecraft.java:280-281,285`; `GameRenderer.java:103-104,125`). The working 26.2 mechanism is SpongePowered `@Mutable @Accessor` mixins (proof: `MOD:mixin/client/MinecraftAccessorMixin.java:34,49`, `MOD:mixin/client/GameRendererAccessorMixin.java:37,44,61,75`, `MOD:mixin/client/LevelExtractorAccessor.java:39`).
6. **`RenderBuffers.endFrame()`** must run once per frame for any mod-created `RenderBuffers` (`net/minecraft/client/renderer/RenderBuffers.java:29`; vanilla calls it at `GameRenderer.java:447`) — already learned the hard way (GPU-buffer leak, commit history).

## Top-risk summary (hardest gaps)

1. **World-switch render (G1/C1/C11):** `renderLevel` draws only pre-extracted state; the recursive re-render becomes per-dimension `LevelRenderState`+`LevelExtractor`+extract-then-render choreography, with `@Mutable` swaps of final `Minecraft.levelRenderer`/`levelExtractor`/`GameRenderer` fields. Mechanism proven in `MOD:render/PortalContextSwitch.java`; IP-fidelity ordering (inventory §3.1) must be re-imposed on it.
2. **Cross-portal entity clipping (G2/G3/G23):** per-entity `endBatch` clip bracketing is unportable at the draw layer; per-entity clip needs a submit-order-keyed uniform or a one-entity `SubmitNodeStorage`+`renderAllFeatures` bracket. UNKNOWN-NEEDS-DESIGN — the single hardest 1:1-fidelity item in this slice. (The entity-visibility gate is NOT part of this risk: IP's `shouldRender`-HEAD inject survives signature-identical and ports 1:1, its call site now on the extraction path — S35.)
3. **ImmPtlViewArea (G25/C22-C29):** vanilla `ViewArea` is now a wrapper over private `RotatingSectionStorage` with `(index, sectionNode)` section creation and externalized dirty tracking; the unbounded presets-cached grid needs a redesign, and the redirect point moved to `LevelRenderer.invalidateCompiledGeometry`.
4. **Shader/uniform stack (G5/G9/G10/G11/C41):** no shader programs, no loose uniforms; custom shaders become `RenderPipeline`s + `BindGroupLayout` UBOs; the clip-plane vec4 rides a raw-GL per-draw hook (`GlCommandEncoder.trySetup`) that is GL-backend-only.
5. **Vulkan backend exists (fact 4, G36, S29):** every raw-GL mechanism (clip planes, stencil, occlusion queries, mirror cull-flip) silently has no Vulkan path; occlusion queries have no vanilla abstraction at all (timestamp pools only).
6. **Reversed-Z (fact 3, C43):** depth clear 0.0, compare `GREATER_THAN_OR_EQUAL` — all view-area depth punching, far-plane writes, and depth-mask combinations in the stencil/FBO renderers must flip.
7. **Immediate mesh drawing (G7/G8/G40):** Tesselator/BufferUploader/BLIT_SCREEN gone; portal-area mesh and screen triangles become GpuBuffer uploads + manual `RenderPass` draws per the SkyRenderer pattern; depth clamp is raw-GL only.
8. **Cross-dim pump pair (G26/S19):** `lateUpdateLight` survives 1:1 (already ported); `earlyRemoteUpload` becomes per-secondary-dispatcher `lock/uploadTerrainBuffersToGpu/unlock` — whether the new staging path can still strand async compiles without it needs runtime verification.
